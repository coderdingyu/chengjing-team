# 模块契约

骨架已经固定技术栈、包名、路由层次和统一返回格式。以下是团队实现时的边界，接口可在 PR 中补充字段，但修改共享契约需要说明依赖模块和迁移步骤。

| 模块 | 拥有后端包 | 前端目录 | API 前缀 | 输入／输出关系 |
| --- | --- | --- | --- | --- |
| A 账号与隐私 | `com.chengjing.identity` | `src/features/identity` | `/api/v1/auth`、`/api/v1/account` | 向其余模块提供当前用户 ID；账号数据只允许本人访问 |
| B 面试准备 | `com.chengjing.preparation` | `src/features/preparation` | `/api/v1/preparation` | 输出岗位案例、准备计划、本人经历素材；C 只引用 ID 与已确认素材 |
| C 面试进行 | `com.chengjing.interview` | `src/features/interview` | `/api/v1/interviews` | 引用用户与案例；输出题目、回答文本、澄清意图与会话状态给 D |
| D 评分与成长 | `com.chengjing.assessment` | `src/features/assessment` | `/api/v1/assessments` | 消费 C 的文本回答与证据；输出维度评分、复盘与成长记录 |
| E 模型与平台 | `com.chengjing.platform` | `src/features/platform` | `/api/v1/models`、`/api/v1/system` | 提供模型 Port 与持久化配置；业务模块不得直接调用供应商 SDK |

## 通用约束

1. 公开 API 返回 `ApiResponse<T>`；成功时 `success=true`，失败时返回明确的错误信息和合适的 HTTP 状态码。不要把 Java 异常或密钥交给浏览器。
2. 模块内部使用领域对象；跨模块用小型 DTO／Port。避免 C 直接读 B 的数据库表，也避免 D 修改 C 的回答记录。
3. A 的账号 ID 是个人数据所属键。B/C/D/E 保存可回溯记录时都带上用户 ID，并在服务端验证访问权限。
4. AI 调用经 E 的模型接口。C 负责对话业务与意图；D 负责评分规则、证据与校准；E 负责供应商接入与密钥隔离。
5. 用户同意前不能打开麦克风或摄像头。摄像头只做本机预览；不保存原始音视频，不以外貌给分。
6. 每项功能至少提供一种有效验收：后端测试、前端测试，或文档中可重复的人工步骤。PR 中写明实际验证结果。

最小接口已经有 `GET /api/v1/system/health`。其余接口随对应任务提交，先实现可用的窄功能，再扩展字段。旧系统同名模块可作为参考：[源码仓库](https://github.com/coderdingyu/chengjing)。
