## 1. 背景与目标

求职者通常知道岗位要求，却难以把自己的经历组织成有证据、可追问的回答。普通题库只给标准答案，不能还原面试官的澄清、追问、思考时间和整场节奏；只有一个总分的反馈也很难指导下一次练习。澄镜将准备、完整模拟、证据复盘和针对性重练连成一个闭环，让用户知道自己**说了什么、哪些能力有证据、下一次具体练什么**。

产品首先服务个人练习，不作招聘录用或人格判断。AI 面试官模拟真实交流，但明确标识为 AI；评分属于训练反馈，不表示真实招聘结果、能力认证或录用概率。摄像头用于本机沉浸预览，外貌、表情、性别、年龄和声音特征不得进入能力评分。

本期交付目标是：

1. 用户能从选择岗位、准备经历、完成一场文字或语音模拟，到查看有原话依据的复盘并重练薄弱题，走通完整流程。
2. 五个模块各交付六项可验收功能，合计 30 项。每项由实际开发者独立提交、测试并通过 PR 合并；提交数是协作要求，不代替产品验收。
3. 在模型不可用、语音断线或页面刷新时，已保存的草稿和回答不丢失；不能以模拟结果冒充真实模型评价。
4. 用户可管理账号、个人数据和模型配置；系统能在本机运行，并具备后续迁移到服务器的配置与操作说明。

## 2. 用户、场景与范围

| 角色 | 主要目标 | 权限边界 |
| --- | --- | --- |
| 求职者 | 准备经历、进行练习、查看复盘、重练、管理数据 | 只访问和修改自己的计划、回答、评分、配置与账号 |
| 仓库维护者 | 合并功能、部署与诊断系统 | 开发权限不等于查看用户明文密钥或绕过业务鉴权 |
| AI 服务商 | 按用户选定的配置处理必要的文本或语音请求 | 仅接收完成当前任务所需的数据；供应商故障不得伪造成功结果 |

目标场景包括应届生准备首轮面试、转岗者梳理可迁移经历、有经验求职者练习项目深挖，以及在一场模拟后反复修正薄弱回答。默认使用简体中文；岗位案例先覆盖分工表规定的 11 类岗位情境。

**本期范围**：账号与隐私、岗位准备、完整模拟面试、文字与可选语音交互、三维面试官、证据评分、成长与复习、个人模型配置、本机部署和服务器迁移准备。

**不在本期 30 项内**：招聘官工作台、候选人排名、自动录用判断、测谎或情绪识别、视频上传和录像回放、社交分享、自动投递。邮箱验证与找回密码、正式公网部署可列入后续迭代，不能在本期尚未实现时宣称可用。原仓库早期面向招聘官的《需求分析书》不是新仓库的交付基线。

## 4. 核心业务流程

### 4.1 首次使用与准备

用户注册或登录，选择目标岗位及练习时长，浏览岗位情境；创建个人准备计划，填写或整理经历素材，并标记哪些是本人确认的事实、哪些只是模拟案例。系统生成项目背景、个人行动、取舍和结果等深挖节点。用户可先做单题专项练习，再进入整场模拟。岗位案例和题目材料应保留版本，避免历史报告因案例更新而改变含义。

### 4.2 完整模拟面试

用户选择岗位、时长和已确认素材后创建本人房间。建议提供 15、30、45 分钟目标时长，至少经过开场、经历/项目、岗位案例和结束反问等环节；超时给提示，不强行丢弃正在输入的回答。面试官每次只提出一个清楚的问题，并结合当前岗位、题目、最近回答追问。用户可回答，也可请求澄清、重听或思考时间。澄清/重听不计为正式作答；索要标准答案时，面试官应说明练习边界并引导继续回答，不能把提示伪装成用户的经历。

文字是始终可用的基础交互。草稿自动保存；刷新后可继续本人未结束的房间。暂停时停止计时和收音，结束后不可再提交该场回答。重复提交同一请求不能产生两份回答。Live 模式中默认先完整播放面试官语音，由用户主动打断；若提供自动插话模式，须单独开启且不能因用户刚开口就截断尚未说完的面试官问题。

### 4.3 复盘与持续练习

回答先持久化，再异步评分。未完成评价时显示处理中或失败可重试，不能展示伪造分数。报告按题呈现原问题、本人回答、四维证据、未覆盖项和最多数项可执行的下一步练习建议。用户可把薄弱回答加入复习清单，重答并并排查看前后原话；只有岗位、题目、量表和提示条件可比时才展示分差。成长趋势只在同一岗位或同一维度的可比记录之间计算，不把不同岗位简单排名。

### 4.4 账号和模型设置

用户可查看/修改个人资料、改密码、导出本人数据、确认后注销账号。用户可以选择内置文本供应商或自定义兼容站点，分别指定对话、评分、语音与 Live 用途；只有经过协议适配的实时模型才出现在 Live 选择中。页面只显示密钥是否已配置，不回显密钥。第一次把面试内容发送到所选第三方模型前，页面说明处理范围和供应商，并取得用户确认。

## 5. 功能需求与追踪

下表的编号与 [30 项功能分工](30项功能分工.md)一一对应。分工表中的“具体验收”是每项提交的最低验收条件；以下补充产品约束和跨模块关系。

### 5.1 A：账号与隐私

| 编号 | 需求 | 关键规则 |
| --- | --- | --- |
| A01 | 注册与格式校验 | 邮箱唯一；密码不能明文保存；错误信息可理解但不泄露内部实现 |
| A02 | 登录、登出与短期令牌 | 登出后旧令牌不可继续访问本人资料；受保护 API 统一鉴权 |
| A03 | 当前用户与个人资料 | 仅本人读取或修改；其他模块以服务端当前用户 ID 作为归属依据 |
| A04 | 修改密码与会话失效 | 校验旧密码；修改成功后旧会话失效 |
| A05 | 个人数据导出 | 导出本人准备、练习、复盘；不包含模型密钥或他人数据 |
| A06 | 账号注销与确认 | 二次确认；清理活跃存储中的本人数据及密钥；说明备份保留边界 |

### 5.2 B：面试准备

| 编号 | 需求 | 关键规则 |
| --- | --- | --- |
| B01 | 11 类岗位情境目录 | 可按岗位浏览情境、任务和目标；案例不含真实个人简历 |
| B02 | 岗位准备计划 | 用户设定目标岗位、练习方向；列表只显示本人计划 |
| B03 | 简历深挖节点 | 节点覆盖背景、个人行动、取舍、结果；可保存完成状态 |
| B04 | 个人经历素材库 | 增删改查与搜索；本人事实和虚构/模拟情境必须显著区分 |
| B05 | 单题专项练习 | 从节点启动问题、保存文字回答；错误时保留草稿 |
| B06 | 复习清单 | 只根据真实已评价回答推荐；重答记录时间，未评价不算达标 |

### 5.3 C：面试进行

| 编号 | 需求 | 关键规则 |
| --- | --- | --- |
| C01 | 创建并查看面试房间 | 按岗位、时长建立本人房间；刷新可继续；越权访问被拒绝 |
| C02 | 文字作答与对话记录 | 问答有确定顺序；重复提交幂等；用户输入视为数据而非系统指令 |
| C03 | 澄清、重听、思考请求 | 三类意图有明确回应，不混入评分回答；追问围绕当前上下文 |
| C04 | 草稿、暂停、继续与结束 | 草稿可恢复；暂停停止计时与采集；结束进入复盘且状态不可逆 |
| C05 | 环节推进与预计时长 | 呈现当前阶段和剩余目标时间；切换阶段不丢草稿 |
| C06 | 三维面试官与视频预览 | 至少三种可切换形象；摄像头单独同意、本机预览、关闭即停轨道 |

### 5.4 D：评分与成长

| 编号 | 需求 | 关键规则 |
| --- | --- | --- |
| D01 | 四维评分规则 | 覆盖问题目标、个人行动、分析取舍、验证反思；缺证据为“未覆盖” |
| D02 | 证据评分 | 每个得分引用回答中的真实原话与理由；不接受模型编造的引文 |
| D03 | 二次评分校准 | 分歧时复核；保存初评、复核、分歧原因、最终依据和规则版本 |
| D04 | 单场面试复盘 | 已完成回答、覆盖情况、下一步建议；后台评分中的状态可见 |
| D05 | 个人成长记录 | 同岗位同维度展示趋势与练习次数；不可比较时说明原因 |
| D06 | 错题再练与证据对照 | 保留原回答与新回答；并排比较证据，不覆盖历史评分 |

### 5.5 E：模型与平台

| 编号 | 需求 | 关键规则 |
| --- | --- | --- |
| E01 | 本机持久化与迁移 | 用户、计划、面试、评分和配置重启不丢；空库迁移可重复执行 |
| E02 | 供应商、模型和密钥配置 | 内置供应商与自定义兼容站点；密钥服务端加密保存、写入后不回显 |
| E03 | 文本模型网关 | 对话和评分经统一 Port；超时、限流、协议错误显式呈现，不静默伪造结果 |
| E04 | 语音转写与朗读 | 同意后采集；定稿字幕可编辑；朗读可重听；不持久化原始音频 |
| E05 | 原生 Live 双向语音 | 完整播放、主动打断、断线文字可恢复；首次连接单独同意 |
| E06 | 本机和服务器部署 | 新克隆可构建、启动并健康检查；无真实密钥的示例和备份恢复说明 |

## 6. AI、评分与语音专项规则

### 6.1 模型任务分工

对话模型负责结合岗位、当前问题和最近回答生成澄清或追问；评分模型负责按固定量表给出结构化候选评价；业务服务负责鉴权、会话状态、意图归类、证据原文核验和最终保存。模型输出不能直接修改用户事实、会话归属或评分规则。用户提供的简历、回答、案例文本均为不可信输入，不能覆盖系统指令。请求仅携带当前任务必要内容，并记录模型、提示词及量表版本以支持复核。

默认文本方案沿用用户选择的 StepFun Step 5 Preview；配置入口也允许其他已适配供应商或自定义 Chat Completions 兼容站点。模型名称和可用性以用户账号实测为准，不把文本模型当成 Live 模型。Live 语音先完成一种经过验证的原生实时协议，其他供应商仅在协议适配并通过连接测试后开放。没有有效密钥时，文字草稿和历史查看仍可用；依赖模型的追问或评分明确显示未完成。

### 6.2 评分解释与校准

四维量表建议使用 0～4 等级并固定描述；每个维度可标记“未覆盖”，此状态不等于 0 分。评分结果至少包含问题 ID、回答 ID、维度、等级、逐字证据、解释、量表版本、模型版本与生成时间。服务端验证证据是该次回答的连续原文；引文不存在、指向其他回答或只凭字数/关键词作判断时拒绝结果并进入重试或人工待处理状态。二次 AI 复核是自动一致性检查，不能宣传为经过真人面试官标定。上线前应以经同意的样本安排人工盲评，检查不同岗位和回答风格下的分歧。

### 6.3 语音轮次与失败处理

传统语音模式把临时字幕和最终字幕分开，用户可编辑定稿后提交。Live 模式默认“听完提问再回答”，提供明显的手动打断按钮；可选自动插话必须经过设备实测，避免环境声或用户轻声回应截断面试官。麦克风、摄像头分别请求权限；停止、暂停、离开房间或注销时关闭采集。网络断开后显示重连入口，已经确认的文本轮次保留，未确认的音频不假装已保存。语音不可用时可切回文字，不要求重开整场面试。

## 7. 信息结构与界面要求

首页突出“继续上次练习”“开始一场模拟”“下一项复习”三个主要行动。一级区域按准备、面试、复盘/成长组织，账号和模型配置收进统一设置入口；五个开发模块不必机械地成为五个并列导航项。面试页把题目、回答、阶段进度和语音控制放在同一任务视图，减少来回跳转。评分页先展示证据与可执行建议，再展示汇总数字。

动效用于状态反馈：面试官倾听/思考/说话状态、环节切换、评分生成进度；不得让长动画阻碍作答。用户开启“减少动态效果”时关闭非必要动画，低性能设备可切换简化形象。至少验证桌面与 375 像素内容宽度，关键操作可用键盘完成；字幕、错误和按钮状态不能只靠颜色区分。

## 8. 数据、权限和接口

主要数据对象包括：`User`、`ModelProfile`、`ScenarioVersion`、`PreparationPlan`、`Experience`、`InterviewSession`、`QuestionTurn`、`AnswerTurn`、`Assessment`、`Evidence`、`ReviewItem`、`ConsentRecord`。所有个人对象均带用户 ID；会话和回答保留创建时间、状态、关联的岗位/案例版本。导出包含可理解的本人训练数据及来源，不包含认证令牌和模型密钥。注销清理活跃存储中的本人数据，备份中的处理方式在部署文档中说明。

| 资源/操作 | 未登录 | 本人 | 其他登录用户 |
| --- | --- | --- | --- |
| 浏览公共岗位案例 | 允许 | 允许 | 允许 |
| 创建和查看个人计划、素材、房间、复盘 | 拒绝 | 允许 | 拒绝 |
| 修改账号、导出、注销 | 拒绝 | 允许，敏感操作再确认 | 拒绝 |
| 查看模型密钥明文 | 拒绝 | 拒绝；仅可更新或删除 | 拒绝 |

公开 API 统一使用 `/api/v1` 和 `{success,data,message}`；用合适的 HTTP 状态表示参数错误、未登录、越权、状态冲突和上游失败。跨模块仅传必要的 DTO/Port：A 提供当前用户身份，B 提供案例与素材引用，C 提供已提交的文本回答，D 输出评分与复盘，E 提供持久化和模型能力。业务模块不得直接读取其他模块的表或把供应商密钥传给浏览器。

## 9. 非功能需求

| 编号 | 类别 | 验收要求 |
| --- | --- | --- |
| NFR-01 | 安全 | 密码使用适合密码存储的哈希；所有个人资源按服务端用户 ID 鉴权；越权和登出后访问有自动测试 |
| NFR-02 | 密钥与网络 | API Key 服务端加密保存、前端不回显；自定义站点默认要求 HTTPS，生产环境阻止访问本机/内网地址，避免服务端请求被滥用 |
| NFR-03 | 隐私 | 摄像头仅本机预览；原始音视频默认不落盘；在采集和第三方模型传输前分别展示同意信息 |
| NFR-04 | 可靠性 | 回答先保存再评分；重试幂等；刷新/重启后恢复草稿和已提交内容；失败状态可见且可重试 |
| NFR-05 | 可观测 | 记录请求 ID、任务状态、耗时、错误类别和模型版本；日志不含密码、密钥、原始音视频或完整敏感简历 |
| NFR-06 | 可用性 | 模型和语音异常可回到文字流程；按钮操作立即显示状态；后台评分不阻塞继续查看或作答 |
| NFR-07 | 兼容性 | Java 17、Node.js 22 可构建；主流 Chromium 浏览器可用；不支持摄像头/麦克风时文字流程仍可完成 |
| NFR-08 | 可访问性 | 关键流程键盘可达、焦点可见；字幕与错误有文字描述；尊重减少动态效果设置 |
| NFR-09 | 可维护性 | 模块契约、迁移脚本和环境变量示例随代码更新；每个功能 PR 有可重复的验收证据 |
| NFR-10 | 部署与恢复 | 全新克隆可按 README 启动并通过健康检查；备份恢复在隔离环境演练；服务器上线前再做 HTTPS、数据库和监控验收 |

## 10. 验收方案与交付顺序

单项功能按 [30 项功能分工](30项功能分工.md)逐条验收。整体验收至少覆盖以下连续场景：注册登录 → 选岗位和案例 → 建计划与经历 → 单题练习 → 创建完整面试 → 文字回答及澄清 → 暂停刷新恢复 → 结束 → 后台评分完成 → 查看原话证据 → 加入复习清单并重答 → 导出或注销本人数据。另分别验证真实模型配置、语音同意与断线、3D 形象切换、跨账号越权、错误模型输出、服务重启恢复、全新克隆构建。涉及第三方模型的语义质量测试应标注供应商和测试条件；无真实密钥时不能把模拟测试写成真实接入通过。

建议按依赖组织合并：

1. **基础**：E01、A01～A03、B01，以及共享用户 ID、案例 ID 和持久化契约。
2. **文字闭环**：B02～B05、C01～C05、E03、D01～D04，完成可恢复的整场文字面试与证据复盘。
3. **成长与体验**：B06、D05～D06、C06、E04～E05，完成重练、三维形象和语音。
4. **隐私与交付**：A04～A06、E02、E06，并完成跨模块数据导出/注销、密钥隔离与本机部署验收。

各成员可并行开发本模块可独立验收的部分；依赖功能未合并时用明确的接口契约或测试替身，不把占位功能宣称完成。每项功能对应一个实际开发者的功能提交和 PR，合并前核对测试、作者、任务编号与验收结果。

## 11. 风险与待确认项

| 风险/待确认项 | 处理原则 |
| --- | --- |
| 模型回答慢、费用或限流 | 显示等待与失败状态；可保存文字回答、稍后单独重试；配置用途和调用额度 |
| Live 语音在设备上打断不稳定 | 默认完整听题、手动打断，保留传统转写与文字模式；真实设备回归后再放开自动插话 |
| AI 评分不稳定或偏向表达风格 | 证据原文核验、二次复核、量表版本化和人工盲评；不宣称录用预测 |
| 五人同时修改入口、DTO 或迁移 | 公共契约变更先在 PR 说明影响，按依赖顺序合并并重跑检查 |
| 私有仓库访问 | 负责人邀请四位组员；每人用自己的 GitHub 账号与验证邮箱提交，不能代署名 |
| 未来服务器地址、域名、SMTP 尚未确定 | 本期先完成本机运行及迁移准备；公网发布和邮件投递在拿到环境后另行验收 |

本文若与 30 项分工的具体交付范围冲突，先通过 PR 同步修改两份文档，再实施代码变更，避免口头扩项造成验收不一致。
