# B03 简历深挖节点

## 验收对照

| 分工表要求 | 实现 |
| --- | --- |
| 为计划生成项目背景、个人行动、取舍、结果等节点 | `ResumeNodeCatalog.forRole` 按岗位给出四个节点模板：`BACKGROUND`／`ACTION`／`TRADEOFF`／`RESULT`，`POST /api/v1/preparation/plans/{planId}/nodes` 写入计划 |
| 每个节点状态可保存 | `PATCH /api/v1/preparation/plans/{planId}/nodes/{nodeId}` 可分别保存 `status`（TODO／DRAFTING／DONE）与 `content`，互不覆盖 |

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/preparation/plans/{planId}/nodes` | 列出本人计划的节点 |
| POST | `/api/v1/preparation/plans/{planId}/nodes` | 生成节点；`focus` 为经历方向，`replace=true` 时清空重做 |
| PATCH | `/api/v1/preparation/plans/{planId}/nodes/{nodeId}` | 保存单个节点的状态与内容 |
| DELETE | `/api/v1/preparation/plans/{planId}/nodes/{nodeId}` | 删除单个节点 |

## 设计说明

- 节点挂在计划上，归属校验复用 `PreparationPlanService.requireEntry`：别人的计划返回 403「这条准备计划属于其他账号，不能查看或修改」，不存在的计划返回 404「准备计划不存在」。
- 生成节点是幂等的：重复点「生成节点」只补齐缺失的节点类型，已经写好的内容不会被覆盖；只有本人显式 `replace=true` 才会清空重做。
- 只写内容不点完成时，节点自动进入 `DRAFTING`，避免状态与内容互相矛盾；`DONE` 必须由本人显式标记。
- 节点模板只包含岗位场景与提问方式（例如「一次线上故障排查或接口性能优化」），不含任何真实简历内容，可以安全展示。

## 测试

`backend/src/test/java/com/chengjing/preparation/PlanNodeTest.java`

- `generatesBackgroundActionTradeoffAndResultNodes`：生成四个节点、类型与顺序正确、`focus` 进入提问文本、列表可回读。
- `keepsEveryNodeStatusAndContentSeparately`：只写内容得到 `DRAFTING`，第二个节点标记 `DONE` 不影响第一个节点的状态与内容。
- `regeneratingKeepsWrittenNodes`：重复生成保留已写内容；`replace=true` 后回到 `TODO` 且内容清空。
- `rejectsOtherAccountsAndInvalidInput`：他人账号 GET／POST／PATCH 均为 403；非法状态 400；不存在的节点 404；不存在的计划 404。

## 人工验收步骤

1. 在 `/modules/preparation/plans` 创建一份计划，点「进入深挖地图」。
2. 填写经历方向后点「生成节点」，确认出现项目背景、个人行动、取舍判断、结果验证四个节点。
3. 在任一节点写入内容后点「保存草稿」，确认状态变为「草稿中」；刷新页面内容仍在。
4. 点另一个节点的「标记为已讲清」，确认第一个节点的状态与内容没有被改动。

## 对其他模块的影响

- 只新增 `com.chengjing.preparation` 下的类型与一条前端路由，不改动 `shared`、`assessment` 与既有 `preparation` 接口。
- 前端新增路由 `/modules/preparation/plans/:planId/nodes`；`App.tsx` 仅增加两行。
