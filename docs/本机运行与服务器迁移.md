# 本机运行与服务器迁移

## 从新克隆启动

需要 Java 17、Node.js 22、npm；Windows 可双击根目录 `启动团队版.cmd`，或者执行 `powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1`。脚本先运行 `npm ci`、前端构建与后端测试/打包，再启动隐藏的本地进程并请求健康接口。成功后访问 `http://127.0.0.1:5173/`；停止用 `停止团队版.cmd`。日志和进程记录在 `.run/`，不纳入 Git。

启动脚本只管理它自己启动的进程。8081 或 5173 被其他程序占用时，应先停止占用程序再启动。模型 API Key 从登录后的模型配置页面保存；前端和 `.env.example` 不包含真实密钥。

## 数据文件与备份

默认数据库是 `backend/data/chengjing.mv.db`，Flyway 在首次启动时执行迁移。模型 API Key 在数据库中加密，主密钥在 `backend/data/master.key`；**两者必须一起备份和恢复**。文件都被 `.gitignore` 排除。生产环境可通过 `CHENGJING_MASTER_KEY`（32 字节 Base64）或 `CHENGJING_MASTER_KEY_FILE` 指定主密钥，切换密钥前先安排数据迁移；仅替换文件会导致已有密钥无法解密。

本机备份步骤：先运行 `scripts/stop-local.ps1`，再运行 `scripts/backup-local.ps1 -Destination C:\安全备份\chengjing-日期`。恢复前同样停止服务，执行 `scripts/restore-local.ps1 -Source C:\安全备份\chengjing-日期 -Force`。恢复脚本会校验 SHA-256；`-Force` 表示覆盖当前数据库，建议先单独备份当前数据。备份目录含可解密模型密钥的主密钥，请保存在受控位置。

## Docker 与后续服务器

有 Docker 的主机可在仓库根目录执行 `docker compose -f deploy/compose.yml up -d --build`。镜像用 Node 22 构建前端，用 Maven/Java 17 测试并打包后端，最终由同一个 JAR 提供页面、API 和 WebSocket；访问 `http://127.0.0.1:8081/` 并验证 `/api/v1/system/health`。容器数据落在 `deploy/data/`，迁移服务器时停服务后复制整个目录，再在新服务器启动相同镜像版本。Docker 卷中的数据库和主密钥不能进入仓库。

服务器使用域名时，让 HTTPS 反向代理转发 `/`、`/api` 和 `/ws` 到 8081，并把 `CHENGJING_ALLOWED_ORIGINS` 配置为实际 HTTPS 页面域名，以允许 Live WebSocket 握手。默认 Docker 端口只绑定本机；需要外部反代时按网络拓扑调整 `CHENGJING_BIND`。根目录 `deploy/.env.example` 只有非敏感示例值。

## 验收边界

- 自动检查：`backend/.\mvnw.cmd -s .mvn/settings.xml test`、`frontend/npm run build`；E01 测试覆盖重复迁移及重启后记录，E02 覆盖密钥加密与账号隔离，E03 覆盖模型响应格式和错误，E05 覆盖 Live 票据及转写持久化。
- E04 的浏览器验收见 [传统语音步骤](E04-语音验收.md)；E05 的真实音频验收见 [Live 步骤](E05-Live验收.md)。CI 没有第三方模型密钥，不能证明供应商实时音频权限已开通。
- A/B/C/D 的跨模块记录接入仍由各自任务负责；E01 的 `PlatformRecordStore` 是持久化基础接口，不能把未接入的数据称为已持久化。
